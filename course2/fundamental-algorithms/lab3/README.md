## Сборка и проверка

Программы собираются в папку `build/`.

```sh
make                              # gcc -std=c99 -Wall -Wextra -Wpedantic -g ... -lm  ->  build/lab3_taskN
make test                         # все тесты
make memcheck                     # все тесты под valgrind
bash run_tests.sh 1               # тесты одного задания
bash run_tests.sh --memcheck 1    # то же под valgrind
./build/lab3_task1 255 4          # запуск одной программы
make clean                        # удалить build/
```

Файл тестов (`tests/tests_taskN.txt`): первая значимая строка `program: <имя>`, далее блоки, разделенные пустой строкой.
Поля блока: `args` (аргументы; аргумент с пробелами - в кавычках), `input` (строка стандартного ввода),
`out` / `outre` (строка stdout; `outre` - регулярное выражение POSIX ERE), `err` (строка stderr), `code` (код возврата),
`file` / `fout` (файл, который должна создать программа, и его строки). Строки сравниваются целиком, без учета пробелов в конце.
Пути в тестах (`tests/data/...`) указаны относительно папки лабораторной (где лежат `Makefile` и `run_tests.sh`).

## Проверка утечек и ошибок памяти

`make memcheck` запускает каждый тест под

```sh
valgrind -q --leak-check=full --show-leak-kinds=definite,indirect,possible \
         --errors-for-leak-kinds=definite,indirect,possible --track-origins=yes --error-exitcode=99
```

Тест считается непройденным, если valgrind завершился с кодом 99 (ошибка доступа к памяти или утечка).
Та же проверка выполняется GitHub Actions при каждом push. На Windows (сборка `zig cc`) утечки дополнительно
проверены Dr. Memory и heob.

## Замечания по заданиям

**Задание 1.** Запуск: `lab3_task1 <число> <r>` (r = 1..5, основание 2^r) или без аргументов - демонстрация.
В функции перевода `to_base_pow2` только битовые операции и обращения к памяти: сложение - своя функция `bit_add`
(`a ^ b` и перенос `(a & b) << 1`), вычитание - `a + ~b + 1`, цифра - `value & mask` с маской `~(~0 << r)`,
переход к следующей цифре - `value >> r`. Модуль отрицательного числа - `~x + 1`, поэтому работает и `LLONG_MIN`
(его модуль 2^63 не помещается в `long long`). Цифры больше 9 - заглавные латинские буквы (A = 10, ..., V = 31).
Разбор числа из командной строки - это ввод, а не перевод, поэтому в нем обычная арифметика; `strtoll` не
используется, потому что о переполнении он сообщает через глобальную `errno`.

**Задание 2.** Ввод - из стандартного потока: `n k`, затем `n` строк `id HH:MM HH:MM`; вывод - одно число.
Алгоритм жадный: доклады по возрастанию времени окончания (`qsort` копии массива), каждый ставится в зал,
освободившийся позже всех, но не позже начала доклада; если такого зала нет - доклад пропускается.
Время - минуты 0..1439, поэтому залы хранятся массивом `free_at[1440]` (сколько залов освобождается в минуту t):
поиск зала - не больше 1440 шагов, а k может быть любым до `LLONG_MAX`. Доклад «в одну минуту кончился -
другой начался» в один зал помещается (интервалы полуоткрытые). Время строго `HH:MM` с двумя цифрами
(`9:00`, `24:00`, `10:60` - ошибки); id положительные и разные. Ответ проверен полным перебором на Python
(набор годится, если ни в какую минуту не идет больше k докладов): 3000 случайных случаев и 12 в тестах.

**Задание 3.** Запуск: `lab3_task3 <файл>`. Файл читается в режиме `rb` кусками по 64 КБ; частоты - массив
на 256 значений. Дерево - массив узлов (не больше 511), куча - своя (массив номеров узлов, «поднять» и
«опустить»). При равных весах условие разрешает любой порядок; чтобы вывод был одинаковым на любой системе,
порядок задан: листья нумеруются по возрастанию значения байта, новые узлы - следующими номерами, из узлов с
равным весом первым берется узел с меньшим номером, и он становится левым (код 0). Вывод: таблица
`byte frequency code` (байты по возрастанию), `Original size: N bytes`, `Encoded size: B bits = M bytes`
(M = B / 8 с округлением вверх), `Savings: X.XX%` = 100 · (1 − M / N); для пустого файла таблица пуста, все
числа 0. Файл из одного значения байта - код `0`. Ответы проверены тем же алгоритмом на Python (`heapq`).

**Задание 4.** Одна программа: тип `String` (создание из `char *`, очистка, порядок - сначала по длине, потом
лексикографически, равенство, копирование в существующую и в новую `String`, конкатенация; демонстрация -
команда `demo`) и почтовое отделение на этом типе. Запуск без аргументов: сначала 6 строк адреса отделения,
потом команды `add`, `remove <id>`, `find <id>`, `list`, `deliver <id>`, `delivered`, `expired`, `office`, `demo`,
`help`, `exit`. После `add` поля вводятся по одному; неправильное поле - сообщение и повторный вопрос.
Подсказки печатаются, только если ввод идет с клавиатуры (`isatty`), поэтому в тестах только ответы.
Массив отправлений всегда упорядочен по индексу, затем по id: новое отправление вставляется сразу на свое место.
*Замечание по условию:* по одному времени нельзя различить «доставлено» и «срок истек», поэтому «время вручения»
понимается как срок вручения, а факт вручения отмечает команда `deliver`: `delivered` - отмеченные, `expired` -
не отмеченные, у которых срок раньше системного времени; оба списка - по времени создания от старых к новым.
Проверки: город и улица непустые, дом и квартира 1..2147483647, корпус любой (может быть пустым), индекс - 6 цифр,
вес - цифры и не больше одной точки, id - 14 цифр и не повторяется, время - настоящая дата (високосные годы)
в формате `dd:MM:yyyy hh:mm:ss`, срок вручения не раньше создания. Метка BOM в начале ввода пропускается.

**Задание 5.** Запуск: `lab3_task5 <файл студентов> <трассировочный файл>`, потом команды со стандартного ввода:
`find id|surname|name|group <значение>`, `sort id|surname|name|group`, `list`, `trace <id>`, `trace best`, `help`, `exit`.
Строка файла: `id имя фамилия группа` и 5 оценок; id - целое ≥ 0 и не повторяется, имя и фамилия - латинские
буквы, группа - слово без пробелов, оценки - 0..100 (условие диапазон не задает; так подходят и пятибалльные, и
стобалльные). Оценки - динамический массив `unsigned char`. Сортировка - `qsort` с компаратором поля; при равных
значениях - по id, чтобы порядок не зависел от реализации `qsort`. Поиск по строкам - точное совпадение с учетом
регистра. «Средняя выше средней по всем» сравнивается в целых числах: `sum * n > total` - точно, без вещественных
чисел и eps. Трассировочный файл создается заново при запуске; он не может быть файлом студентов - проверяются
сами файлы (`stat` / `_fullpath`), в том числе через `./` и `../`.

**Задание 6.** Запуск: `lab3_task6 <файл пункта> [...]`, потом команды: `routes max|min`, `path max|min`, `route max|min`,
`stop max|min`, `idle max`, `list`, `help`, `exit`. Формат файла пункта (условие его не задает): первая строка -
координаты `x y`, дальше записи `номер dd.MM.yyyy hh:mm:ss dd.MM.yyyy hh:mm:ss метка` (прибытие, отправление,
метка `start` / `middle` / `end`). Хранилище - односвязный список маршрутов, у каждого маршрута - номер транспорта и
односвязный список остановок по времени. Сборка: записи всех файлов раскладываются по транспорту (список транспорта
упорядочен по номеру, остановки вставляются по времени), потом остановки каждого транспорта режутся на маршруты
`start ... end`; если последовательность нарушена или остановки пересекаются по времени - ошибка с номером транспорта.
Длина маршрута - сумма расстояний по прямой между соседними пунктами; «путь» транспорта - сумма длин его маршрутов;
простой - сумма длительностей всех его остановок. Длины сравниваются с eps (параметр функций, 1e-9), время - в целых
секундах (дата переводится в секунды от 01.01.0001 с учетом високосных лет). При равенстве - первый по номеру.

**Задание 7.** Запуск: `lab3_task7 <файл жителей>`, потом команды: `list`, `find <поле> <значение> [...]` (поля
`surname name patronymic birth gender income`; несколько пар - все должны совпасть; `patronymic -` - без отчества),
`add`, `edit <номер>`, `delete <номер>` (номер - как в `list`), `save` (путь - следующей строкой), `undo`, `help`, `exit`.
Строка файла: `фамилия имя [отчество] дд.ММ.гггг M|W доход` - без отчества 5 слов. Дата рождения не позже сегодняшней.
Список упорядочен от младших к старшим, при равных датах - в порядке добавления. Undo отменяет последние ⌊N/2⌋
изменений (`add`, `edit`, `delete`) в обратном порядке; N - сколько изменений с чтения файла или с прошлой отмены.
В журнале у каждого изменения - позиции «до» и «после» и копия старых данных: так отмена возвращает жителя точно
на прежнее место (даже среди жителей с той же датой). Если ⌊N/2⌋ = 0, отменять нечего и журнал не очищается.
Отмена проверена моделью на Python, в которой отмена - возврат к сохраненному снимку списка: 400 случайных
сценариев совпали. Доход при поиске сравнивается с eps; в файл пишется `%.15g` (без лишних нулей).

## Сборка и проверка

Программы собираются в папку `build/`.

```sh
make                              # gcc -std=c99 -Wall -Wextra -Wpedantic -g ... -lm  ->  build/lab2_taskN
make test                         # все тесты
make memcheck                     # все тесты под valgrind
bash run_tests.sh 1               # тесты одного задания
bash run_tests.sh --memcheck 1    # то же под valgrind
./build/lab2_task1 -r hello       # запуск одной программы
make clean                        # удалить build/
```

Файл тестов (`tests/tests_taskN.txt`): первая значимая строка `program: <имя>`, далее блоки, разделенные пустой строкой.
Поля блока: `args` (аргументы; аргумент с пробелами - в кавычках), `input` (строка стандартного ввода),
`out` / `outre` (строка stdout; `outre` - регулярное выражение POSIX ERE), `err` (строка stderr), `code` (код возврата),
`file` / `fout` (файл, который должна создать программа, и его строки). Строки сравниваются целиком, без учета пробелов в конце.
Пути в тестах (`tests/data/...`) указаны относительно папки лабораторной (где лежат `Makefile` и `run_tests.sh`): `run_tests.sh` запускает программы из нее.

## Проверка утечек и ошибок памяти

`make memcheck` запускает каждый тест из `tests/tests_task*.txt` (включая ветви с ошибочным вводом) под

```sh
valgrind -q --leak-check=full --show-leak-kinds=definite,indirect,possible \
         --errors-for-leak-kinds=definite,indirect,possible --track-origins=yes --error-exitcode=99
```

Тест считается непройденным, если valgrind завершился с кодом 99 (ошибка доступа к памяти или утечка); в конце выводится итог по каждому заданию.

Результат проверки (Ubuntu в WSL 2, gcc 15.2.0, valgrind 3.26.0): сборка с `-Werror` без предупреждений, все тесты пройдены,
valgrind - 0 ошибок и 0 утечек. Та же проверка выполняется GitHub Actions при каждом push (`.github/workflows/check.yml` в корне репозитория).
На Windows (сборка `zig cc`, Universal CRT) те же тесты проходят; утечки дополнительно проверены Dr. Memory 2.6.0 и heob 4.2.

## Замечания по заданиям

**Задание 1, флаг `-c`.** По условию генератор засевается функцией `srand`, поэтому используется стандартная пара
`srand`/`rand`. Формула `rand` в стандарте не задана: при одном и том же seed порядок склейки на Linux (glibc) и
Windows (UCRT) различается, а на одной системе всегда повторяется. Поэтому тесты проверяют результат `-c`
регулярным выражением (любая перестановка строк). Строки обрабатываются побайтно (`char`): для текста в UTF-8
длина `-l` - это число байт.

**Задание 2.** Запуск: `lab2_task2 <входной файл> <-a|/a|-d|/d> <выходной файл>`. Строка файла - `id имя фамилия зарплата`;
любая неправильная строка - ошибка с номером строки, выходной файл тогда не создается. id - целое от 0 до `LLONG_MAX`
(разбирается вручную, `-1` и `1.5` - ошибки), имя и фамилия - только латинские буквы, зарплата - цифры с необязательной
дробной частью через точку. Компаратору `qsort` нельзя передать eps (прототип задан, глобальные переменные запрещены),
поэтому при чтении зарплата один раз переводится в целое число единиц eps (`salary_to_units`, eps = 10^-6), а компаратор
сравнивает целые числа: зарплаты, равные с точностью eps, равны, и порядок транзитивен (прямое `fabs(a - b) < eps` в
компараторе этого не дает). Отсюда предел зарплаты ~9.22e12. Фамилии и имена сравниваются без учета регистра, при
совпадении - с учетом (`Ivanov` раньше `ivanov`). Последний признак - текст зарплаты: так выходной файл одинаков на любой
системе. Зарплата пишется в выходной файл тем же текстом, что во входном (без округления). Вход и выход - один файл
(в том числе `./in.txt` и `in.txt`) - ошибка: сравниваются файлы (`stat` / `_fullpath`), а не строки путей.

**Задание 3.** Функция с переменным числом аргументов `find_substring(&result, substring, count, path1, path2, ...)`
находит в каждом файле все вхождения подстроки (с перекрытием: `aa` в `aaaa` - 3 вхождения) и возвращает их
строки и позиции (с 1, позиция - в байтах); печатает результат `main`. Подстрока может содержать перевод строки.
Файл читается по одному символу, в памяти - только «окно» из последних m символов (m - длина подстроки), поэтому
размер файла не ограничен памятью. `strstr` и `strncmp` не используются. Файл, который не открылся, отмечается
в результате, поиск в остальных продолжается (код возврата 1). Без аргументов - демонстрация с готовыми списками
файлов из `tests/data/` (запускать из папки лабораторной). С аргументами `<подстрока> <файл>...` файлы ищутся
по одному (`find_substring(&result, substring, 1, argv[i])`); в подстроке понимаются `\n`, `\t`, `\\`.
Файлы открываются в режиме `"rb"`, поэтому позиции одинаковы на Windows и Linux. На Windows аргументы командной
строки приходят в кодировке системы (cp1251), а не UTF-8, поэтому русскую подстроку в UTF-8 файле так не найти;
на Linux - находится.

**Задание 4.** Задача о рюкзаке решается точно. Файлы больше вместимости и файлы с важностью 0 отбрасываются;
если оставшиеся помещаются все вместе, берутся все (так обрабатывается огромная вместимость, например 10^18).
Иначе выбирается способ, которому нужно меньше всего работы: таблица по размеру (`n * (capacity + 1)` клеток),
таблица по важности (`n * (сумма важностей + 1)`) или полный перебор (`2^n`, при n <= 22). Таблицы ограничены
10^7 клеток; если ни один способ не проходит, выводится ошибка `the task is too big`, а не попытка выделить
гигабайты памяти. Числа - `long long`, разбираются вручную с проверкой переполнения (`-1`, `+5`, `1.5` - ошибки).
Имена любой длины (строки читаются через `realloc`), уникальность имен проверяется сортировкой (`qsort`).
Ошибка выводится, только если не помещается в `long long` важность самого ответа.

**Задание 5.** `overfprintf(FILE *, const char *, ...)` и `oversprintf(char *, const char *, ...)` имеют прототип
`fprintf`/`sprintf` (по условию), поэтому возвращают `int`: число выведенных символов или -1 при ошибке; остальные функции
возвращают статус-код. У обеих одно ядро `over_vprintf`, которое пишет либо в поток, либо в строку (структура `output`),
без временных файлов; `va_list` передается в функции по указателю. Стандартные спецификаторы (флаги, ширина и точность,
в том числе `*`, модификаторы `hh h l ll j z t L`, `%n`) разбираются вручную: аргумент нужного типа достается из списка
и передается `vsnprintf` по одному. Результаты сверены со стандартной `snprintf` на 200000 случайных спецификаторов.
`%Ro`: от -3999 до 3999 (0 печатается как `N`), иначе -1. `%Zr`: 0 печатается как `01`. `%to`/`%TO`: строка проверяется
(регистр букв, цифры меньше основания, необязательный `-`, результат в диапазоне `int`), иначе -1. `%to` в C99 - это
`%o` с модификатором `t`, но по условию это новый флаг. Дампы `%mi %mu %md %mf` - байты по порядку адресов (на x86 и ARM
младший байт первый). Режим командной строки: `lab2_task5 <флаг> <значение> [основание]`. `%Lf` (long double) в
стандартной библиотеке Windows (UCRT) не поддерживается, поэтому в демонстрации его нет.

**Задание 6.** `overfscanf(FILE *, const char *, ...)` и `oversscanf(const char *, const char *, ...)` имеют прототип
`fscanf`/`sscanf` (по условию) и возвращают `int`: число записанных значений или `EOF`, если ввод кончился, а ни одного
значения не записано (так ведут себя glibc и UCRT, даже если перед этим был `%*d`); `EOF` - и при `NULL` или неверном
формате. Одно ядро `over_vscanf` читает либо из потока, либо из строки (структура `source`: один символ вперед через
`ungetc`, счетчик прочитанных символов для `%n`), без временных файлов. Новые флаги `%Ro %Zr %Cv %CV` (и с `*`) читаются
по одному символу, как их печатает задание 5 (`-XIV`, `N` = 0, `01` = 0 в `%Zr`); как и `%d`, сначала пропускают пробелы.
`%Zr` заканчивается на `11`, поэтому коды можно писать подряд без пробелов. Неподходящие символы и числа, не помещающиеся
в `int`/`unsigned int`, останавливают чтение без переполнения. Стандартные спецификаторы (`*`, ширина, модификаторы длины,
`[набор]`, `%n`, `%%`) разбираются вручную и по одному передаются `vfscanf`/`vsscanf` с дописанным `%n` - так ядро знает,
сколько символов прочитано. Сверено со стандартными `sscanf`/`fscanf` на 100000 случайных форматов и строк (возвращаемое
значение, все переменные, позиция в файле): в glibc совпадение полное; UCRT перед `%%` не пропускает пробелы (по стандарту
должна), здесь сделано по стандарту. Режим командной строки: `lab2_task6 <Ro|Zr|Cv|CV> [основание]` читает значения из
стандартного ввода.

**Задание 7.** Функция с переменным числом аргументов `find_longest(&result, eps, n, vector_count, norm_count, v1, ..., f1, param1, ...)`
принимает векторы как экземпляры структуры `vector` (по значению), а нормы - парами «указатель на функцию нормы, указатель
на ее параметр» (`const void *`: адрес числа p, адрес матрицы или `NULL`). Все нормы имеют один тип `norm_func` - универсальный
тип указателя на функцию, их различия спрятаны в параметре. Параметр нормы передается в `...` с приведением `(const void *)`,
так как тип аргумента функция узнать не может (просто `NULL` может оказаться `int`). Вектор считается самым длинным, если ни один
другой вектор не длиннее его больше чем на eps: так находятся все равные самые длинные, без сравнения вещественных чисел
без eps. Норма `||x||_A` считается через разложение Холецкого A = L L^T: оно же проверяет симметричность и положительную
определенность матрицы, а `(Ax, x) = |L^T x|^2` не бывает отрицательным. Перед вычислением норм p и A координаты делятся
на `max |x_j|` (норма однородна), поэтому `(1e200, 1e200)` не дает переполнения, а большое p - нуля. Ошибка одной нормы
(p < 1, плохая матрица) не останавливает остальные. В режиме командной строки используется вариант с массивами
`find_longest_array` (то же ядро), так как число аргументов `...` должно быть известно при компиляции.

**Задание 8.** Числа хранятся строками и складываются поразрядно (`add_in_base`), поэтому их длина не ограничена
встроенными типами. Функция с переменным числом аргументов `sum_in_base(&result, base, count, ...)` принимает числа
как `char *`. При запуске с аргументами командной строки числа прибавляются к сумме по одному
(`sum_in_base(&result, base, 2, sum, argv[i])`), так как количество аргументов `...` должно быть известно при компиляции.
На входе цифры-буквы допускаются в любом регистре, в ответе - заглавные; ведущие нули удаляются.

**Задание 9.** Функция с переменным числом аргументов `check_fractions(&result, eps, base, count, x1, ..., xk)`
для каждого числа x из (0; 1) возвращает дробь p/q, конечность записи в системе `base` (2..36) и для конечной дроби -
саму запись (`0.0011`). Число `double` хранится в двоичном виде (0.1 - это не ровно 1/10), поэтому сначала ищется
несократимая дробь p/q, отличающаяся от x меньше чем на `eps` (первая подходящая дробь цепной дроби x), затем
проверяется, что все простые делители q делят основание: q делится на НОД(q, base), пока НОД > 1, и должна остаться 1.
Десятичная дробь с d знаками после точки находится точно, если `eps <= 10^(-2d)`: при eps = 10^-12 - до 5-6 знаков
(`0.33333` -> 33333/100000, конечна в десятичной), а при большом eps находится более простая дробь (`0.33333` с eps = 10^-3 -> 1/3).
Числа, которые с точностью eps равны 0 или 1, а также вне (0; 1), inf и nan - ошибка этого числа; остальные числа
обрабатываются. Цифры записи считаются без умножения `remaining * base` (сложением с вычитанием q), поэтому переполнения нет
при любом q до `LLONG_MAX`. В режиме командной строки числа передаются функции по одному
(`check_fractions(&result, eps, base, 1, x)`), так как число аргументов `...` должно быть известно при компиляции.

**Задание 10.** Переразложение выполняется «на месте» многократным делением на `(x - a)` по схеме Горнера
(`horner_shift`, около n²/2 операций, одно выделение памяти под ответ). Функция с переменным числом аргументов
`polynomial_reexpand(eps, a, &g, n, f0, ..., fn)` принимает коэффициенты как `double` (литералы нужно писать `1.0`, а не `1`).
Режим с аргументами командной строки вызывает вариант с массивом `reexpand_array` (тот же алгоритм), так как число
аргументов `...` должно быть известно при компиляции. Коэффициенты, меньшие `eps` по модулю, считаются нулем
(убирает шум округления вида 1e-18). Ответ проверяется подстановкой: f(x) и g(x - a) сравниваются в точках x = -2..2
с относительной точностью `|f - g| <= eps * (1 + |f|)`. Бесконечности, NaN и переполнение при вычислении - ошибки.

## Сборка и проверка

Программы собираются в папку `build/`.

```sh
make                              # gcc -std=c99 -Wall -Wextra -Wpedantic -g ... -lm  ->  build/lab4_taskN
make test                         # все тесты
make memcheck                     # все тесты под valgrind
bash run_tests.sh 1               # тесты одного задания
bash run_tests.sh --memcheck 1    # то же под valgrind
./build/lab4_task1 tests/data/task1_example.txt --stats          # запуск одной программы
make clean                        # удалить build/
```

Файл тестов (`tests/tests_taskN.txt`): первая значимая строка `program: <имя>`, далее блоки, разделенные пустой строкой.
Поля блока: `args` (аргументы; аргумент с пробелами - в кавычках), `input` (строка стандартного ввода),
`out` / `outre` (строка stdout; `outre` - регулярное выражение POSIX ERE), `err` (строка stderr), `code` (код возврата),
`file` / `fout` (файл, который должна создать программа, и его строки). Строки сравниваются целиком, без учета пробелов в конце.
Пути в тестах (`tests/data/...`) указаны относительно папки лабораторной (где лежат `Makefile` и `run_tests.sh`).

## Проверка утечек и ошибок памяти

`make memcheck` запускает каждый тест под

```sh
valgrind -q --leak-check=full --show-leak-kinds=definite,indirect,possible \
         --errors-for-leak-kinds=definite,indirect,possible --track-origins=yes --error-exitcode=99
```

Тест считается непройденным, если valgrind завершился с кодом 99 (ошибка доступа к памяти или утечка).
Та же проверка выполняется GitHub Actions при каждом push. На Windows (сборка `zig cc`) утечки дополнительно
проверены Dr. Memory и heob.

## Замечания по заданиям

**Задание 1.** Запуск: `lab4_task1 <файл> [--stats]`. Текст после директив печатается в стандартный поток вывода;
с `--stats` перед ним - состояние хеш-таблицы (размер, самая короткая и самая длинная цепочка, число пересборок).
Заменяются только целые слова (самые длинные цепочки латинских букв и цифр), как в препроцессоре C: `PI` заменяется
в `(PI)+1`, но не в `PIE` и `xPI`. Вставленное значение повторно не просматривается (директивы не вкладываются).
Повторный `#define` с тем же именем заменяет значение. Раздел директив кончается на первой строке без `#define`.
Хеш - имя как число по основанию 62 по модулю HASHSIZE; число считается по модулю 2^64 (переполнение
`unsigned long long`) и **кэшируется** в элементе таблицы. HASHSIZE - всегда степень двойки (128, 256, ...), а для
неё `N mod 2^k = (N mod 2^64) mod 2^k`, поэтому хеш точный, а пересборка не просматривает имена заново.
Равномерность: самая длинная цепочка должна быть меньше двух самых коротких; пустые корзины не считаются (пока
макросов меньше, чем корзин, пустые корзины неизбежны, и по букве условия таблица была бы неравномерной всегда).
При нарушении перебираются размеры 128..65536: берётся самый маленький равномерный, а если такого нет - самый
равномерный, и только если он лучше текущего. Ожидаемый вывод тестов и стресс-тест (300 случайных файлов,
с `--stats` и без) - эталон на Python `docs/src/эталоны/t1.py`.

**Задание 2.** Запуск: `lab4_task2 <файл с инструкциями> [--seed N]`; файл для демонстрации - `tests/data/task2_demo.txt`.
Массивы A..Z вначале пустые; команды разделяются `;`, регистр не важен, `Free(A)` можно писать и без скобок.
Ошибка в команде (запись или выполнение) - сообщение с номером команды и строки в stderr, затем выполняются следующие
команды; код возврата 1, если ошибки были. `Load` заменяет содержимое массива, неправильные элементы пропускает
(предупреждение с их числом). `Remove`, `Copy`, `Print` проверяют индексы; `Save` в файл с инструкциями запрещён
(сравниваются файлы, а не строки путей: `same_file`). Случайные числа - свой генератор xorshift64, начальное число -
`--seed` (без него - время). `Shuffle` сделан через `qsort`, как требует условие: элементам даются случайные ключи,
сортировка по ключам (компаратор со случайным ответом нарушил бы правила `qsort`). Среднее в `Stats` считается
точно: каждый элемент делится на n с остатком, среднее = сумма частных + сумма остатков / n - без переполнения и без
`long double` (его точность разная у компиляторов и под valgrind). Самый частый элемент - по отсортированной копии;
при равной частоте - наибольший. Эталон и стресс-тест (300 случайных программ) - `docs/src/эталоны/t2.py`.

**Задание 3.** Запуск: `lab4_task3 <файл с инструкциями> [eps]` (eps по умолчанию 1e-9); демонстрация -
`tests/data/task3_demo.txt`. Многочлен - двусвязный список одночленов, упорядоченный (сначала большая суммарная
степень, затем переменные по алфавиту); одночлен - коэффициент `double` и бор «переменная - степень» (переменных
со степенью 0 в боре нет). Запись одночлена: множители через `*` или `_`, число может стоять вплотную к имени
(`4xy` = 4·`xy`: имена бывают длинными, поэтому `xy` - одна переменная); повторы имён и чисел перемножаются,
отрицательная степень внутри одночлена допустима, итоговая - нет (`x1^3_x1^-1` = `x1^2`). Знак после множителя-числа
или имени начинает новый одночлен, после `*`/`_`/`^` - это знак множителя (`_-2.1`). Регистр имён переменных не
важен, имена инструкций - с учётом регистра. Инструкции `Add`, `Sub`, `Mult`, `Eval`, `PartDeriv`, `Cmps` - из
условия; для остального требуемого функционала добавлены `Grad({точка})` (градиент в точке; печатается, сумматор
не меняется) и `PartInteg(f, x)` (первообразная по x). `Cmps(f, x, g)` - в f вместо x подставить g: у многочленов
от нескольких переменных подставляют в конкретную переменную. Без первого параметра берётся сумматор; результат
`Eval` (число) тоже идёт в сумматор. Ошибка в инструкции - сообщение, сумматор не меняется, дальше следующая.
Коэффициент, меньший eps по модулю, - ноль. Эталон повторяет программу шаг в шаг (тот же порядок операций с
`double`), поэтому числа совпадают до цифры; стресс-тест - 400 случайных программ (`docs/src/эталоны/t3.py`).

**Задание 9.** Запуск: `lab4_task9 <max_priority> <файл параметров> <файлы заявок> [--log <файл>] [--seed N]`;
журнал без `--log` - в стандартный вывод; `--seed` - начальное число генератора (имена операторов, время обработки).
Файл параметров - строки из условия по порядку (пустые пропускаются): очередь (`BinaryHeap`, `BinomialHeap`,
`FibonacciHeap`, `SkewHeap`, `LeftistHeap`, `Treap`), словарь (`HashSet`, `DynamicArray`, `BinarySearchTree`, `Trie`),
начало и конец (ISO 8601 `YYYY-MM-DDTHH:MM:SS`, секунды можно опустить), минимальное и максимальное время обработки
(минуты), число отделений, операторы через пробел, коэффициент перегрузки. Отделения называются `1`..`n`. Шесть очередей
и четыре словаря - общие интерфейсы (таблицы указателей на функции `heap_ops`, `map_ops`); у очереди есть добавление,
поиск и извлечение самой важной заявки, слияние с разрушением (`meld`) и без (`pq_meld_copy`). Порядок: больший
приоритет, при равном - раньше поступившая. Шаг - минута: заявка между шагами поступает на следующем. На шаге:
окончания обработки, свободные операторы (по порядку) берут заявки, поступления по одной (заявку сразу берёт свободный
оператор). Перегрузка - в очереди не меньше `операторы * коэффициент` (коэффициент - точная дробь, `1.25` = 125/100,
без `double`): вся очередь передаётся `meld` наименее загруженному отделению ((занятые + очередь) / операторы), которое
после передачи само не перегружено; такого нет - в журнале «no department can take them». Пустые минуты не перебираются
(сразу к ближайшему событию). В конце - итоги. Ошибки в заявках (время, приоритет, отделение, кавычки, раньше начала
модели) - в stderr и в журнал, остальные заявки обрабатываются, код возврата 1. Журнал не может быть входным файлом
(`same_file`). Все 24 сочетания очереди и словаря дают одинаковый журнал. `lab4_task9 --self-test [--seed N]` -
самопроверка всех операций интерфейса у всех очередей и словарей (в модели не вызываются `top`, `collect` и слияние
без разрушения): порядок извлечения сравнивается с `qsort`, после `pq_meld_copy` исходные очереди не меняются. **9.2:** `lab4_task9_config <файл>` -
вопросы по очереди (печатаются только при вводе с клавиатуры), неправильный ответ - сообщение и тот же вопрос; операторы
- одно число для всех или по числу на отделение. **9.3:** `lab4_task9_generate <max_priority> <файл параметров>
<файлы заявок> [--seed N]` - аргументы как у 9.1; в каждом файле 10..100 заявок со случайными временем (целые минуты
модели, по возрастанию), приоритетом, отделением и текстом. Модель на Python (очередь - список и `max`) и стресс-тест
(300 случайных моделей по всем 24 сочетаниям, генератор) - `docs/src/эталоны/t9.py`.

**Задание 10.** Запуск: `lab4_task10 [<файл настроек>] <файл программы> [--base_assign N] [--base_input N]
[--base_output N] [--debug | -d | /debug]` (основания 2..36, по умолчанию 10). Без файла настроек берётся последний,
с которым работала программа: его полный путь запоминается при завершении в `lab4_task10_settings.txt` рядом с
программой (в `build/`). Переменные - `uint32_t` в боре (с удалением узлов при отмене объявления), арифметика по
модулю 2^32, `pow` - быстрое возведение в степень, деление и остаток на 0 - ошибка. В условии сказано и «прописные и
строчные буквы [в именах переменных] не отождествляются», и «различий между прописными и строчными буквами нет»:
регистр различается в именах переменных и не важен в названиях команд и цифрах констант. Константа начинается с
цифры (при `base_assign` 16 `FF` - имя, константа - `0FF`). Настройки: `<команда> <синоним>` (действует последний
синоним, прежнее название перестаёт работать; синоним - слово или значок вроде `<>`; одинаковые названия у двух команд
- ошибка), `left=`/`right=`, `op()` и `()op` (для унарных и бинарных команд), `(op)` (только для бинарных:
`a add b`, цепочка слева направо без приоритетов, скобки - для группировки); по умолчанию `left=` и `op()`.
Комментарии `#` и `[ ]` (вложенные) - и в настройках, и в программе. Значки разбираются по самому длинному
совпадению (`!=` раньше `!`). Инструкция - присваивание, `input(x)` (строка ввода в `base_input`) или `output(e)`
(в `base_output`); `input`/`output` внутри выражения - ошибка. Инструкция разбирается в дерево и сразу выполняется;
ошибка (синтаксическая или времени выполнения) - сообщение с номером строки, остановка, код 1. Глубина вложенности
не больше 500, узлов в инструкции не больше 2000 (рекурсия разбора и вычисления ограничена). Отладчик (`--debug`):
комментарий `# BREAKPOINT` - остановка там, где его встретил разбор (инструкции до него выполнены); действия 1-7 из
условия, значения - в 16-ричной системе, дамп - байты в порядке в памяти; объявление - цекендорфово представление
(как в лабораторной 2: от младшего числа Фибоначчи, `1` в конце, 10 = `010011`) или римские цифры (I..MMMCMXCIX);
ошибки - `Debugger error: ...`, диалог продолжается; конец ввода - выполнение продолжается. Подсказки отладчика - только
при вводе с клавиатуры. Вторая реализация на Python и стресс-тест (1000 случайных настроек и программ с вводом и
командами отладчика) - `docs/src/эталоны/t10.py`.

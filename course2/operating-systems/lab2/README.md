# Операционные системы, лабораторная работа 2

Потоки в Windows. Вариант 11: наложить K раз медианный фильтр на матрицу целых чисел,
размер окна задаётся пользователем. Наибольшее число потоков, работающих одновременно, задаётся ключом.

## Запуск

```
median_filter -t T -w W -k K                    матрица со стандартного ввода
median_filter -t T -w W -k K -g R C SEED        случайная матрица R x C: время и контрольная сумма
median_filter -t T -w W -k K -g R C SEED -b     замер для 1..T потоков: время, ускорение, эффективность
median_filter                                   без ключей (или двойной щелчок по exe): программа сама
                                                спрашивает T, W, K, размеры и строки матрицы
```

Без ключей программа задаёт вопросы по очереди (только если ввод с клавиатуры), на неправильный ответ
просит ввести его снова, печатает результат, число потоков и время и ждёт Enter, чтобы окно не закрылось.
Каждая строка матрицы вводится отдельной строкой. На первый вопрос вместо числа потоков можно ввести
всю строку ключей (`-t 4 -w 3 -k 1 -g 1500 1500 1 -b`) - программа поработает как при запуске с ними.

| Ключ | Значение |
|---|---|
| `-t T` | наибольшее число потоков, 1..64 (столько ждёт `WaitForMultipleObjects`); больше, чем строк, не создаётся |
| `-w W` | размер окна W x W, нечётное число 1..99 |
| `-k K` | сколько раз наложить фильтр, 0..1000 |
| `-g R C SEED` | случайная матрица R x C (числа 0..999), SEED - начало генератора (одинаковый SEED - одинаковая матрица) |
| `-b` | только с `-g`: замер для 1, 2, ..., T потоков |

Ввод со стандартного ввода: число строк, число столбцов, затем все элементы (любые `int`) через пробелы
и переводы строк. Вывод - матрица в том же виде, без размеров.


## Сборка

Нужны Windows, [zig](https://ziglang.org/download/) (или gcc из MinGW) и Git Bash / MSYS2 с `make`.

```sh
make                  # build/median_filter.exe
make test             # все тесты (tests/tests_median_filter.txt)
make memcheck         # все тесты под Dr. Memory
```

## Как устроено

- **Медианный фильтр.** Каждый элемент заменяется медианой W*W чисел окна вокруг него: числа окна
  упорядочиваются (`qsort`), берётся среднее. За краем матрицы берётся ближайший элемент края.
- **Fork & Join.** На каждом из K проходов строки делятся между T потоками поровну (первые `R % T` потоков
  получают на строку больше); потоки создаются `CreateThread`, главный поток ждёт их
  `WaitForMultipleObjects` и проверяет коды завершения `GetExitCodeThread`.
- **Синхронизация не нужна.** Проход читает одну матрицу и пишет в другую; каждый поток пишет только свои
  строки. Следующий проход начинается после завершения всех потоков; матрицы меняются ролями.
- **Одинаковый результат при любом T** проверяется контрольной суммой (`h = h * 31 + элемент`):
  в тестах и в режиме `-b`.
- **Время** измеряется `QueryPerformanceCounter` и включает только фильтр (без создания матрицы).

## Число потоков средствами ОС

Диспетчер задач -> Подробности -> столбец «Потоки» (столбец включается правым щелчком по заголовку), Process
Explorer -> вкладка Threads, или в PowerShell `(Get-Process median_filter).Threads.Count` во время работы.
Ожидается T потоков фильтра + главный поток (+ несколько служебных потоков загрузчика Windows в первые
секунды жизни процесса). Номер процесса программа печатает в режиме `-g`.

## Тесты

`tests/tests_median_filter.txt` (формат описан в начале файла). Ожидаемые матрицы и контрольные суммы
посчитаны на Python тем же генератором и тем же фильтром. Есть тесты на одинаковый результат при 1 и 7-8
потоках, на T больше числа строк, на K = 0 и нечётное K, окно 1 и 99, границы `int`, файл с BOM и `\r\n`,
и на все ошибки ключей и ввода.

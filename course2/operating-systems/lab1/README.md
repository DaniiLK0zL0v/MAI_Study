## Задание (вариант 11)

**Группа 3:** Родительский процесс создаёт два дочерних процесса. Child1 и Child2 соединены между собой дополнительным каналом. Родительский и дочерний процессы представлены **разными программами**.

**Конкретный вариант:**
- **Child1** — переводит строки в верхний регистр
- **Child2** — заменяет все пробельные символы на символ «_»

---

## Схема межпроцессного взаимодействия

```
  +---------+        pipe1        +--------+      pipe_mid      +--------+        pipe2        +---------+
  |         | ==================> |        | ==================> |        | ==================> |         |
  |  User   |   stdin    stdout   | child1 |   stdout    stdin   | child2 |   stdout    stdin   |  User   |
  |  (ввод) | <-- parent  write   | (upper)|   write     read   | (sp->_)|   write     read -> | (вывод) |
  +---------+                     +--------+                     +--------+                     +---------+
                                      ^                                                             |
                                      |                      parent.exe                             |
                                      +-------------------------------------------------------------+
                                                  Чтение ввода / Вывод результата
```

### Потоки данных:

1. Пользователь вводит строку в консоль `parent.exe`
2. `parent` отправляет строку в **pipe1** (запись)
3. `child1` читает из **pipe1** (через перенаправлённый stdin), переводит в верхний регистр, пишет в **pipe_mid** (через перенаправлённый stdout)
4. `child2` читает из **pipe_mid** (через перенаправлённый stdin), заменяет пробельные символы на `_`, пишет в **pipe2** (через перенаправлённый stdout)
5. `parent` читает результат из **pipe2** и выводит пользователю

## Описание файлов

### `parent.c` — Родительский процесс

**Основная логика:**

1. **Создание каналов** — 3 пары анонимных каналов через `CreatePipe()`:
   - `pipe1` (parent -> child1)
   - `pipe_mid` (child1 -> child2)
   - `pipe2` (child2 -> parent)

2. **Управление наследованием дескрипторов** — через `SetHandleInformation()`:
   - Перед созданием child1: делаем наследуемыми только `pipe1_read` и `pipe_mid_write`
   - Перед созданием child2: делаем наследуемыми только `pipe_mid_read` и `pipe2_write`
   - Это предотвращает утечку дескрипторов между процессами

3. **Создание дочерних процессов** — через `CreateProcessA()`:
   - `child1.exe` — stdin перенаправлен на pipe1, stdout на pipe_mid
   - `child2.exe` — stdin перенаправлен на pipe_mid, stdout на pipe2
   - Используется `STARTF_USESTDHANDLES` для перенаправления стандартных потоков

4. **Основной цикл** — чтение строк от пользователя, запись в pipe1 через `WriteFile()`, чтение результата из pipe2 через `ReadFile()` (посимвольно до `\n`)

5. **Завершение** — закрытие каналов, ожидание дочерних процессов через `WaitForSingleObject()`, получение кодов завершения через `GetExitCodeProcess()`

**Обработка ошибок:**
- Проверка возвращаемых значений всех WinAPI-вызовов
- Вывод кода ошибки через `GetLastError()`
- Корректное завершение при ошибке pipe или процесса

### `child1.c` — Перевод в верхний регистр

- Читает строки из stdin (перенаправлен из pipe1) через `fgets()`
- Применяет `toupper()` к каждому символу
- Выводит результат в stdout (перенаправлен в pipe_mid) через `fputs()`
- Вызывает `fflush(stdout)` после каждой строки для немедленной передачи через pipe

### `child2.c` — Замена пробельных символов на «_»

- Читает строки из stdin (перенаправлен из pipe_mid) через `fgets()`
- Проходит по каждому символу:
  - Если символ является пробельным (`isspace()`) и это не `\n` — заменяет на `_`
  - Иначе — оставляет как есть
- Выводит результат в stdout (перенаправлен в pipe2) через `fputs()`
- Вызывает `fflush(stdout)` после каждой строки

## Использованные системные вызовы Windows

| Вызов | Назначение | Где используется |
|-------|-----------|-----------------|
| `CreatePipe()` | Создание анонимного канала | parent.c — создание pipe1, pipe_mid, pipe2 |
| `CreateProcessA()` | Создание нового процесса | parent.c — запуск child1.exe и child2.exe |
| `SetHandleInformation()` | Управление наследованием дескрипторов | parent.c — контроль, какие дескрипторы наследуют дочерние процессы |
| `WriteFile()` | Запись данных в pipe | parent.c — отправка строк в pipe1 |
| `ReadFile()` | Чтение данных из pipe | parent.c — получение результата из pipe2 |
| `WaitForSingleObject()` | Ожидание завершения процесса | parent.c — ожидание child1 и child2 |
| `GetExitCodeProcess()` | Получение кода завершения | parent.c — проверка статуса дочерних процессов |
| `CloseHandle()` | Закрытие дескриптора объекта ОС | parent.c — закрытие pipe-дескрипторов и процессов |
| `GetStdHandle()` | Получение стандартного дескриптора | parent.c — stderr для дочерних процессов |
| `GetLastError()` | Код последней ошибки | parent.c — диагностика ошибок |

## Сборка и запуск

### Сборка с GCC (MinGW):

```bash
gcc -Wall -o child1.exe child1.c
gcc -Wall -o child2.exe child2.c
gcc -Wall -o parent.exe parent.c
```

### Сборка с MSVC:

```bash
cl /W3 /Fe:child1.exe child1.c
cl /W3 /Fe:child2.exe child2.c
cl /W3 /Fe:parent.exe parent.c
```

### Автоматическая сборка:

```bash
build.bat
```

### Запуск:

```bash
parent.exe
```

**Важно:** Все три `.exe` файла (`parent.exe`, `child1.exe`, `child2.exe`) должны находиться **в одной директории**.

## Пример работы

```
[parent] child1 (PID 12345) создан.
[parent] child2 (PID 12346) создан.
[parent] Введите строки (пустая строка или Ctrl+Z для выхода):
-----------------------------------------------------------
> Hello  WORLD   This  Is  A  TEST
Результат: HELLO__WORLD___THIS__IS__A__TEST
> another line with	tabs
Результат: ANOTHER_LINE_WITH_TABS
>
[parent] Ожидание завершения дочерних процессов...
[parent] child1 завершён (код: 0)
[parent] child2 завершён (код: 0)
[parent] Родительский процесс завершён.
```

**Что произошло:**
1. `"Hello  WORLD   This  Is  A  TEST"` → child1 (uppercase) → `"HELLO  WORLD   THIS  IS  A  TEST"` → child2 (spaces→`_`) → `"HELLO__WORLD___THIS__IS__A__TEST"`
2. Результат проходит через оба процесса последовательно

## Ключевые моменты реализации

### Почему важен `fflush(stdout)` в дочерних процессах?

Стандартная библиотека C буферизует вывод. При работе с pipe (а не с терминалом) используется **полная буферизация** (а не построчная). Без `fflush()` данные могли бы застрять в буфере, и parent не получил бы результат.

### Почему важно управлять наследованием дескрипторов?

Если child2 унаследует запись `pipe_mid_write`, то даже после завершения child1 pipe_mid не закроется (child2 держит копию write-дескриптора). Child2 никогда не получит EOF при чтении из pipe_mid. Программа зависнет.

### Почему parent читает посимвольно из pipe2?

`ReadFile()` не знает о границах строк. Если читать блоком, можно захватить часть следующей строки. Посимвольное чтение до `\n` гарантирует получение ровно одной строки-результата на каждый запрос.

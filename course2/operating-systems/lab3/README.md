# Операционные системы, лабораторная работа 3

Разделяемая память (memory mapping) и семафоры в Windows. Вариант 11 (группа вариантов 3).

## Задание

Лабораторная 1, где каналы (pipe) заменены именованной разделяемой памятью, а синхронизация сделана
семафорами. Вариант тот же: родительский процесс принимает от пользователя строки произвольной длины,
child1 переводит их в верхний регистр, child2 превращает пробельные символы в `_`, результат возвращается
родителю и выводится на экран. Требования преподавателя: объект разделяемой памяти - именованный и
в оперативной памяти (не файл на диске), имена у каждого запуска свои, старый API `shmget` не использовать.

```
пользователь -> parent --first--> child1 --middle--> child2 --second--> parent -> экран
```

Каждый "канал" (`first`, `middle`, `second`) - объект разделяемой памяти с буфером на одну порцию
(до 4096 байт) и два семафора: `empty` (буфер свободен, начальное значение 1) и `full` (в буфере порция,
начальное значение 0). Писатель ждёт `empty`, пишет, отпускает `full`; читатель ждёт `full`, читает,
отпускает `empty`.

| Файл | Что делает |
|---|---|
| `channel.h` | общий код канала: создать (`CreateFileMapping` с `INVALID_HANDLE_VALUE`, `MapViewOfFile`, `CreateSemaphore`), открыть (`OpenFileMapping`, `OpenSemaphore`), отправить и принять порцию (`WaitForMultipleObjects`, `ReleaseSemaphore`), закрыть (`UnmapViewOfFile`, `CloseHandle`) |
| `parent.c` | создаёт три канала и событие остановки (`CreateEvent`), запускает детей (`CreateProcess`) и передаёт им префикс имён, имена каналов и свой PID; читает строки, отправляет в `first`, печатает ответ из `second`; в конце ждёт детей (`WaitForSingleObject`, `GetExitCodeProcess`) |
| `child1.c` | открывает каналы `first` и `middle` по именам, латинские буквы -> заглавные |
| `child2.c` | открывает каналы `middle` и `second` по именам, пробельные символы кроме `\n` -> `_` |

## Сборка и запуск

Нужны Windows, [zig](https://ziglang.org/download/) (или gcc из MinGW) и Git Bash / MSYS2 с `make`.

```sh
make                  # parent.exe, child1.exe, child2.exe -> build/
make test             # все тесты (tests/tests_*.txt)
make memcheck         # все тесты под Dr. Memory (проверяет и дочерние процессы)
build/parent.exe      # ввод строк с клавиатуры; конец - Ctrl+Z и Enter
```

Все три программы должны лежать в одной папке: parent ищет детей рядом со своим exe.
Детей запускает только parent: без него им нечего открывать.

## Тесты

`tests/tests_parent.txt` - вся цепочка (те же 15 тестов, что в лабораторной 1: обычные строки, пустые строки,
пробелы по краям, `\r\n`, строка в 30000 символов, 1000 строк). `tests/tests_child1.txt` и `tests_child2.txt` -
ошибки запуска детей (нет аргументов, неправильный PID, объектов с такими именами нет). Формат описан в начале
`tests_parent.txt`. Ожидаемые ответы для файлов из `tests/data` посчитаны на Python.

## Замечания по заданию

- **Память в ОЗУ, а не на диске.** `CreateFileMapping` получает `INVALID_HANDLE_VALUE` вместо описателя файла:
  такая память берётся из оперативной памяти (при нехватке - из файла подкачки) и исчезает, когда закрыт
  последний её описатель.
- **Имена разные у каждого запуска.** Все имена начинаются с `Local\os_lab3_<PID parent>_`, например
  `Local\os_lab3_21764_middle_full`. PID работающего процесса уникален, поэтому два parent, запущенные
  одновременно, не мешают друг другу. Если имя всё же занято (`ERROR_ALREADY_EXISTS`), parent сообщает об ошибке
  и не работает с чужим объектом.
- **Строки любой длины, нет взаимной блокировки.** parent читает строку в буфер, который растёт вдвое
  (`realloc`), и отправляет её порциями по 4096 байт, после каждой порции забирая ответ на неё. Если бы он слал
  порции, не читая ответы, все три буфера заполнились бы и процессы ждали бы друг друга вечно. Оба ребёнка
  заменяют символ ровно одним символом, так что ответ на n байт - ровно n байт.
- **Конец данных** - порция с флагом `end`. Она проходит через child1 и child2 и возвращается к parent;
  каждый ребёнок, переслав её, завершается.
- **Никто не ждёт вечно.** Каждое ожидание семафора - `WaitForMultipleObjects` вместе со "сторожами":
  у parent - описатели процессов детей, у детей - событие остановки и процесс parent (`OpenProcess`).
  Ребёнок завершился раньше времени - parent пишет `Error: parent: a child process ended unexpectedly`
  и взводит событие остановки, второй ребёнок выходит. Завершился parent - дети тоже выходят.
- **Пробельные символы** - те, для которых `isspace()` истинна: пробел, `\t`, `\r`, `\v`, `\f`.
  `\n` не заменяется: это граница строк. Регистр меняется только у латинских букв (`toupper`).
- **Ошибки:** неудача системного вызова - `Error: <программа>: <функция> failed (Windows error N)` и код 1;
  нет child1.exe/child2.exe рядом с parent.exe - `Error: parent: can not start ...child2.exe (Windows error 2)`;
  ребёнок завершился с кодом не 0 - сообщение и код 1.

Вариант 11 - «Банковская карта». Язык Java (совместимость с Java 17).

## Задание

Реализовать 3 класса, образующих корректную иерархию наследования (1 -> 2 -> 3), вокруг заданного класса
(«Банковская карта»; он может стоять на любом уровне). В каждом классе - не менее 3 собственных атрибутов и
не менее 3 собственных методов; свойства (геттеры и сеттеры) обязательны и в число методов не входят.
Иерархия должна быть логически корректной.

## Иерархия

```
FinancialInstrument        финансовый инструмент: владелец, банк, валюта, активен / заблокирован
   └── BankCard            банковская (дебетовая) карта - заданный класс: номер, срок, свои деньги
          └── CreditCard   кредитная карта: кредитный лимит, процентная ставка, долг
```

Каждый следующий класс - частный случай предыдущего («кредитная карта - это банковская карта»,
«банковская карта - это финансовый инструмент»), поэтому наследование логически корректно:
объект подкласса можно использовать везде, где ожидается объект родителя.

| Класс | Собственные атрибуты | Собственные методы (без геттеров и сеттеров) |
|---|---|---|
| `FinancialInstrument` | `holderName`, `issuingBank`, `currency`, `active` | `activate()`, `block()`, `getInfo()`, `getShortName()` |
| `BankCard` | `cardNumber`, `expiryDate`, `balance` | `deposit()`, `pay()`, `getMaskedNumber()`, `isExpired()` |
| `CreditCard` | `creditLimit`, `interestRate`, `debt` | `getAvailableCredit()`, `pay()` (переопределен), `repayDebt()`, `calculateInterest()` |

У всех атрибутов есть геттеры; сеттеры проверяют значение и при неправильном бросают
`IllegalArgumentException` (у `debt` сеттера нет: долг меняется только операциями).
Переопределены `getInfo()` (каждый уровень дописывает свои поля), `getShortName()` (у карты - номер вместо
владельца) и `pay()` (кредитная карта доплачивает кредитными деньгами).

Вспомогательные типы (не входят в иерархию): `OperationResult` - результат операции (`OK`, `CARD_BLOCKED`,
`CARD_EXPIRED`, `NOT_ENOUGH_MONEY`, `NO_DEBT`), `Money` - вывод суммы в копейках как `15000.50`.

## Сборка и проверка

Нужен JDK 17 или новее.

```sh
make            # javac -encoding UTF-8 --release 17 -Xlint:all -Werror  ->  build/classes
make run        # демонстрация (Main)
make test       # Tests + сравнение вывода Main с tests/main_expected.txt
make clean      # удалить build/
```

Без make:

```sh
javac -encoding UTF-8 -d build/classes src/*.java tests/Tests.java
java -cp build/classes Main
java -cp build/classes Tests
```

GitHub Actions (`.github/workflows/check.yml` в корне репозитория) при каждом push выполняет `make` и `make test`.

## Замечания

**Деньги - в копейках (`long`), а не `double`.** `double` хранит число в двоичном виде, и десятичные дроби
в нем неточны (`0.1 + 0.2 = 0.30000000000000004`); для денег это недопустимо. Целые копейки складываются точно.
В коде суммы записаны с подчеркиванием перед копейками: `15000_50` = 15000.50 руб.

**Классы карт ничего не печатают.** Операции возвращают `OperationResult` (обычный отказ банка: карта
заблокирована, не хватает денег), а печатает результат `Main`. Неправильные аргументы (сумма <= 0, номер не из
16 цифр) - ошибка вызывающего кода, для них бросается `IllegalArgumentException`.

**Вывод не зависит от языка системы.** Все сообщения - на английском (русский текст в консоли Windows
искажается), суммы печатаются вручную (`Money.format`), а не `%.2f`, который на русской Windows ставит запятую.

**Сеттеры объявлены `final`.** Их вызывают конструкторы; переопределенный в подклассе метод работал бы
с еще не созданной частью объекта (предупреждение компилятора `this-escape`).

**Срок действия.** Карта со сроком `09/35` работает до конца сентября 2035 года. Просроченной и заблокированной
картой нельзя платить и пополнять ее; долг кредитной карты погашать можно всегда. Проверка
`isExpired(YearMonth)` получает месяц параметром, поэтому тесты не зависят от даты запуска.

**Кредитная карта.** Своя часть денег (`balance`) и долг (`debt`) хранятся отдельно. Оплата сначала тратит
свои деньги, недостающее берет в долг, если хватает доступного кредита (`лимит - долг`); иначе платеж
отклоняется целиком. Лимит нельзя сделать меньше текущего долга. Проценты - простые:
`долг * ставка / 100 / 12 * месяцы`, с округлением до копейки; метод только считает, долг не меняет.
